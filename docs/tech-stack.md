# Tech stack

Libraries and tools by area, each with a status. Phase 1 rows are the build list; later rows show where the stack is heading so Phase 1 code leaves room for them. Every runtime dependency must appear here with a reason (AGENTS.md rule 7). WASM-backed libraries are marked **(WASM)** and must also be in the D-002 inventory.

## Status

| Status      | Meaning for implementers                                                                                                                        |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Decided** | Use it. Changing it needs a new decision entry.                                                                                                 |
| **Default** | Use it now, behind the interface named in Notes where there is one. Revisit at the "Decide by" point, with evidence. Do not switch on your own. |
| **Open**    | Not chosen yet. Evaluate the alternatives before the "Decide by" point (see [decisions.md](decisions.md#decision-points-by-stage)).             |

## Version policy

- Pin exact versions in `package.json` (no `^` or `~`) and commit the lockfile.
- At scaffold time (task T01), fill the **Version** column with the versions actually installed.
- Node: the active LTS line at scaffold time, recorded in `.nvmrc` and `engines`.
- Three.js (Phase 2): upgrade deliberately, one release at a time; `WebGPURenderer` and TSL still change between releases.

## Scaffold tooling pins

T01 installs only the tools needed by the empty workspace; runtime libraries are installed
and pinned by their owning tasks above. Defaults remain defaults, including Drizzle and
React; neither decision was changed by the scaffold.

| Tool           | Version | Reason                                                                                              |
| -------------- | ------- | --------------------------------------------------------------------------------------------------- |
| `@types/node`  | 24.19.2 | Node 24 API types for tooling, server-side packages and tests                                       |
| `tsx`          | 4.23.15 | Cross-platform TypeScript command runner and development watchers                                   |
| TypeScript     | 6.0.3   | Strict compiler and JavaScript compiler API used by the boundary guard                              |
| `vite`         | 8.1.0   | T13 fixture server and bundle inspection, without introducing the T12 app shell                     |
| `three`        | 0.186.1 | Development-only orthographic renderer comparison in the T13 spike; not imported by `@bgp/table-2d` |
| `@types/three` | 0.183.1 | Type declarations for the development-only T13 comparison                                           |

The T13 root development harness also links `@bgp/schema`, `@bgp/table-2d` and
`pixi.js` 8.6.6 to compare the renderers against the same validated fixtures.
Three.js and its optional loaders are excluded from the production renderer.

T08 installs `quickjs-emscripten-core` and `@jitl/quickjs-wasmfile-release-sync`, both
0.32.0, behind `RulesSandbox`. These are the modular distribution of quickjs-emscripten;
installing only the synchronous release variant avoids unused debug/async WASM binaries.
The local package asset is loaded lazily by the server, with no third-party runtime fetch.

| T08 runtime dependency                | Version | Reason                                                                                |
| ------------------------------------- | ------- | ------------------------------------------------------------------------------------- |
| `quickjs-emscripten-core`             | 0.32.0  | Interpreter API behind `RulesSandbox`, without importing unused WASM variants         |
| `@jitl/quickjs-wasmfile-release-sync` | 0.32.0  | Self-hosted synchronous release interpreter; the single server-only D-002 WASM binary |

T08 also pins esbuild 0.28.2 as development tooling to bundle the trusted rules runtime
for evaluation inside the interpreter and to build the disposable VM comparison worker.

Installed direct dependencies use exact versions and the lockfile records transitives.
T07 pins PostgreSQL `postgres:17.11` and Keycloak `quay.io/keycloak/keycloak:26.8.0`; see infra/README.md for upstream release notes.

PixiJS 8.6.6 is pinned deliberately: the inspected 8.14.3, 8.21.0 and 8.22.0 packages ship optional Basis/KTX `.wasm` binaries in the production dependency tree, violating AC-14 even though this renderer does not load those transcoders. 8.6.6 contains none. Re-run `pnpm check:wasm` for every renderer dependency update.
